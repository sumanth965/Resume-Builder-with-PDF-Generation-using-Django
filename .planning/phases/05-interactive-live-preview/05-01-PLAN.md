# 05-01: Live Preview Integration

This plan implements the real-time feedback loop between the resume editor and the preview window using HTMX.

## Tasks

<task id="preview-partial-01">
<title>Create Preview Pane Partial</title>
<read_first>
- `resume_app/templates/resume_print.html`
</read_first>
<action>
1. Create `resume_app/templates/partials/preview_pane.html`.
2. This partial should essentially be a web-optimized version of `resume_print.html` (no `@page` CSS, using Tailwind classes instead).
3. It should render the identity fields, education, and experience lists.
</action>
<acceptance_criteria>
- Partial renders correctly when provided with dummy context.
- Design matches the planned "Modern" aesthetic.
</acceptance_criteria>
</task>

<task id="live-preview-view-01">
<title>Live Preview Logic</title>
<read_first>
- `resume_app/views.py`
</read_first>
<action>
1. Implement `live_preview` view in `views.py`.
2. This view will:
   - Parse POST data (similar to `create_resume`).
   - Construct the context.
   - Return `render(request, 'partials/preview_pane.html', context)`.
3. Register the URL in `resume_app/urls.py`.
</action>
<acceptance_criteria>
- View returns a valid HTML fragment on POST request.
- Data parsing handles dynamic blocks (Education/Experience) correctly.
</acceptance_criteria>
</task>

<task id="editor-integration-01">
<title>Connect Editor to Preview</title>
<read_first>
- `resume_app/templates/form.html`
</read_first>
<action>
1. Update the `<form>` in `form.html` to include:
   - `hx-post="{% url 'live_preview' %}"`
   - `hx-trigger="keyup changed delay:1s, change"`
   - `hx-target="#preview-window"`
2. Add a loading indicator (e.g., a "Syncing..." text) that appears during the HTMX request.
3. Replace the placeholder div in `form.html` with `<div id="preview-window">{% include 'partials/preview_pane.html' %}</div>`.
</action>
<acceptance_criteria>
- Typing in the Education or Experience fields triggers a refresh of the preview pane after a 1s pause.
- Indication is given to the user when syncing is happening.
</acceptance_criteria>
</task>

## Verification

- **Must-have**: Changes in dynamic rows are reflected in the preview without full page reload.
- **Must-have**: Transition between preview states is smooth (using HTMX transitions).
