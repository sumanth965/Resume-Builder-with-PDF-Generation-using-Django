# 03-02: Modern Editor & Interactivity

This plan implements the interactive logic of the resume editor, enabling users to dynamically add/remove sections and see their changes in real-time (basic mirroring).

## Tasks

<task id="dynamic-blocks-01">
<title>HTMX Dynamic List Management</title>
<read_first>
- `resume_app/views.py`
- `resume_app/templates/create_resume.html`
</read_first>
<action>
1. Create `resume_app/templates/partials/education_row.html` and `experience_row.html`.
2. Implement two new views in `views.py`: `get_education_form` and `get_experience_form` which return the partials.
3. Update `create_resume.html` to include "Add Section" buttons using `hx-get` to the new endpoints and `hx-target` to the row container.
4. Implement "Remove" buttons within partials using `hx-on="click: this.closest('.item').remove()"`.
</action>
<acceptance_criteria>
- Clicking "Add Education" appends a new row to the form without page reload.
- Clicking "Remove" deletes the specific row from the DOM.
- Form indices remain manageable (Phase 5 will handle deep submission logic).
</acceptance_criteria>
</task>

<task id="live-mirror-01">
<title>Alpine.js State & Basic Sync</title>
<read_first>
- `resume_app/templates/create_resume.html`
</read_first>
<action>
1. Wrap the editor form in an Alpine.js `x-data` object (e.g., `resumeData`).
2. Bind basic fields (name, email, phone) using `x-model`.
3. Create a placeholder "Preview Content" div that displays the Alpine state variables in real-time.
</action>
<acceptance_criteria>
- Typing in the "Name" field immediately updates the "Preview" text via Alpine.js.
- UI state (e.g., current active tab in editor) is managed via Alpine.
</acceptance_criteria>
</task>

## Verification

- **Must-have**: Dynamic rows (Add/Remove) work seamlessly.
- **Must-have**: Real-time mirroring for core identity fields is active.
