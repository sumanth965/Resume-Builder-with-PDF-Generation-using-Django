# 01-02: Data Migration & Model Validation

This plan focuses on migrating legacy flat-field data into the new relational structure and implementing strict validation rules requested for data consistency.

## Tasks

<task id="migration-01">
<title>Legacy Data Migration Script</title>
<read_first>
- `resume_app/models.py`
- `resume_app/views.py` (for existing parsing helper logic)
</read_first>
<action>
1. Create an empty Django migration using `python manage.py makemigrations --empty resume_app`.
2. Implement a `forwards_func` using `apps.get_model` to iterate through all `Resume` objects.
3. Parse the existing legacy text fields (like `education` and `experience`) using the logic found in `views.py` (but adapted for migration context).
4. Create and save corresponding `Education` and `Experience` related records for each resume.
5. Apply the migration.
</action>
<acceptance_criteria>
- Migration file exists in `resume_app/migrations/` with `RunPython` operation.
- Existing resume records in the database now have related records in the `Education` and `Experience` tables.
- No data is lost from the legacy fields.
</acceptance_criteria>
</task>

<task id="validation-01">
<title>Model Validation & Constraints</title>
<read_first>
- `resume_app/models.py`
</read_first>
<action>
1. Add `RegexValidator` or `DateValidator` to date fields to ensure `YYYY-MM-DD` format (if they aren't standard `DateField`s).
2. Override the `clean()` method in `Resume` to ensure at least one `Education` or `Experience` entry exists before saving (if applicable at model level, sonst logic goes to Phase 2/3).
3. Ensure `blank=False`, `null=False` are correctly applied to mandatory fields as per context.
4. Add basic email and phone formatting validation to the `Resume` model fields.
</action>
<acceptance_criteria>
- `models.py` contains validation logic or specialized Field types.
- Attempting to save a Resume with invalid data (e.g., wrong date format) raises a `ValidationError`.
</acceptance_criteria>
</task>

## Verification

- **Must-have**: All previous resumes have their education and experience data correctly represented in the new related tables.
- **Must-have**: New resumes cannot be created without meeting the strict validation criteria.
