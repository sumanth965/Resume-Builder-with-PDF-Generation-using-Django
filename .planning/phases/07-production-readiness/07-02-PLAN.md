# 07-02: Edit and Update Logic

This plan enables users to modify existing resumes without creating duplicates.

## Tasks

<task id="edit-logic-01">
<title>Editor pre-population</title>
<read_first>
- `resume_app/views.py`
- `resume_app/templates/form.html`
</read_first>
<action>
1. Update `create_resume` view to accept an optional `id` parameter: `create_resume(request, resume_id=None)`.
2. If `resume_id` is provided, fetch the object and pass it to the context.
3. Update `form.html` to pre-populate Alpine.js state with the fetched data if it exists.
4. Correctly parse and render the legacy "Education" and "Internship" textareas during load.
</action>
<acceptance_criteria>
- Navigating to `/edit/1/` loads the data of Resume #1 into the form.
- Live Preview correctly renders the saved data on load.
</acceptance_criteria>
</task>

<task id="update-persistence-01">
<title>Implement Update logic</title>
<action>
1. Modify the POST handler in `create_resume` to use `Resume.objects.update_or_create` based on a hidden `resume_id` field in the form.
2. Ensure the "Download PDF" button triggers the update of the existing record instead of creating a new one when in "Edit" mode.
</action>
<acceptance_criteria>
- Saving an edited resume updates the database entry (no new row created).
- PDF is updated with the latest changes.
</acceptance_criteria>
</task>

## Verification

- **Must-have**: Existing resumes can be modified and downloaded.
- **Must-have**: New resumes can still be created correctly.
