# 04-01: Async Infrastructure (Celery/Redis)

This plan sets up the background task infrastructure using Celery and Redis to handle non-blocking PDF generation.

## Tasks

<task id="celery-setup-01">
<title>Celery Configuration</title>
<read_first>
- `resume_project/settings.py`
- `resume_project/__init__.py`
</read_first>
<action>
1. Create `resume_project/celery.py` with standard Celery app initialization.
2. Update `resume_project/__init__.py` to ensure Celery is loaded on startup.
3. Update `settings.py` with Celery and Redis broker configurations.
4. Add `CELERY_TASK_TRACK_STARTED = True` and results backend settings.
</action>
<acceptance_criteria>
- `python manage.py check` passes.
- Celery app is accessible in the python shell: `from resume_project.celery import app`.
</acceptance_criteria>
</task>

<task id="task-api-01">
<title>PDF Status API & Task Placeholder</title>
<read_first>
- `resume_app/api.py`
</read_first>
<action>
1. Create `resume_app/tasks.py` with a placeholder `generate_pdf_task`.
2. Add a new API view or endpoint to `api.py` that checks `AsyncResult(task_id).status`.
3. Register the status endpoint in `resume_project/urls.py` or the router.
</action>
<acceptance_criteria>
- Endpoint `/api/v1/pdf/status/<task_id>/` returns JSON with status (PENDING, STARTED, SUCCESS).
</acceptance_criteria>
</task>

## Verification

- **Must-have**: Celery configuration is valid.
- **Must-have**: API status endpoint handles invalid/missing task IDs gracefully.
